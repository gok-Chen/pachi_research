# Pachinko／Pachislot 月報撰寫要求

自 2026-11-06 起，新報告與後續修訂沿用以下格式。

- 保留原本的套用可能性、Slot／Fish 玩法說明及舉例；每個「Slot Game 轉用分析」與「Fish Game 轉用分析」末尾均附「機率設計要點套用」。
- 每項原提案分別寫「規格與機率」及「例子」，直接說明每轉、每次有效命中、每場或進入後的判定，以及成功／失敗、獎額、資源、次數與時間限制。
- 依已知原機的獎額分配、入口、續行、重設及狀態轉移，設計對應的轉用規格；圖表有資料時也要閱讀，不只摘錄初當率或續率。原機條件分配不直接當成每轉／每發機率。
- 具體百分比可以是新提出的轉用示例，但明示「非原機規格、尚未校準」。未公開的原機數值不自行補成事實；互斥分支應合計100%，多類別表須列齊。
- 使用簡明規格和例子，避免長篇推導。舊提案有算術矛盾時，在新增段落簡短註明本例採值，不悄悄改掉歷史原文。
- 同機種跨月重複時，保留原完整分析連結，並帶入對應的機率規格與例子，讓當月可以直接閱讀。不同機種依其玩法設計，不一律套同組機率。
- 不同提案先分開示範，若要疊加須另行配平；不得因局部權重合計100%就宣稱整體RTP已校準，也不宣稱選項等價、保證獲利或已驗證留存。
- Markdown與HTML同步；保留原資料擷取日期，另記修訂日期與範圍。檢查原文與舉例保留、兩類套用齊備、內嵌Markdown同步及本機連結存在。未重新查證／模擬／實玩時不冒稱已驗證。

本倉庫以HTML與圖片發布報告；多數Markdown來源依既有.gitignore規則保留於本機。後續發布前應確認HTML及所有引用圖片一併提交。
